# pixiu

The company inside Shanhai, a hands-on security engineering lab: a small version of a real SaaS company, built to be attacked, detected and rebuilt, with every control verified before it counts. It starts as one hardened service and grows into the company a slice at a time.

The repo was called xiezhi until September 2026.

## Design notes

Grows with the build: data flow, trust boundaries, threats (STRIDE) and the control for each.

- **Dependencies:** every runtime package (including transitive ones) is locked to an exact version and hash (`requirements.txt`, generated by `pip-compile --generate-hashes`); the image installs with `--require-hashes`, so what was audited is exactly what ships.
- **Container:** base image pinned by digest; runs as a dedicated non-root user with a numeric UID; build context limited by `.dockerignore`.
- **Container contents:** pip is removed after install. The app never runs it, and the image scan showed it ships its own vendored packages (two HIGH findings) that the lockfile cannot see
- **CI gates (every PR):** tests, a replay of recorded CloudTrail events through the real normalizer and rules, SCA on the lockfile (pip-audit), secret scanning over full history (gitleaks), SAST on Python and the Dockerfile (Semgrep), an image scan of the built image (Trivy, pinned by digest, given only the image tar) and a config scan of the Terraform and Dockerfile (Trivy). The image gate fails on fixable HIGH/CRITICAL and the config gate on HIGH/CRITICAL, the rest are reported
- **Updates:** Dependabot for pip, the base image digest and action SHAs, with a 7-day cooldown so a malicious release is likely pulled before it is proposed
- **Surface:** interactive API docs (`/docs`, `/redoc`, `/openapi.json`) are disabled.
